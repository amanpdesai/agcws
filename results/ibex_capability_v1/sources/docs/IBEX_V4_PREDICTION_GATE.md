# Prediction-envelope readiness gate

Before Stage B, one grounded request of two candidates on a fixed context: the
already measured partial-iteration CPU gate as history slot 1, with observed
development target_0 and unchanged scale. Both returned predictions must refer
to slot 1 and contain eight valid directions; both programs must pass the full
local schema. No simulation, retry, repair or search-quality claim. Keep the
same model/sampling configuration and relaxed native serving schema, extended
with the separate predictions field. Freeze payload, schema and code before the
request. Missing usage or an API failure fails readiness. Preserve any failure
and make a new explicit decision rather than silently repeating the request.
